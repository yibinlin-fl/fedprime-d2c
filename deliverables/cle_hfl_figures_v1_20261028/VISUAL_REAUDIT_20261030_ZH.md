## 图2：优先修正执行语义和几何

### 执行语义（高优先级）

现有直线链条是private minibatch → frozen PEW → support → BER → local f_k → HFL。
这容易被读成“图片先经过BER处理，再进入模型”，与BER作用于训练风险的定义不符。
正确流程至少应分开：

```text
public synthetic supervision → train PEW → freeze
private x → frozen PEW → pseudo-environment
private x → local task model f_k → prediction + task label → per-sample loss
task label + pseudo-environment → class×environment support/weights
loss + groups/weights → BER risk → gradient update of f_k
f_k on public communication inputs ↔ existing HFL protocol
```

BER不处理或修复输入像素；PEW不提供任务预测；通信也不能被画成私有fit logits自动发送服务器。
目前图2的“logits→HFL”缺少公共输入限定，应在修订中说明公共预测通信接口。
正文中BER公式不需要因绘图调整而更改。

### 图片与小图标（已定量确认）

两个技术图均采用9×3.75in画布、默认subplot和0—1坐标，并用aspect='auto'放图。
实际横纵单位像素比例为2.415584，坐标中的宽高相同不代表显示尺寸相同。

图2public source与各变体还使用不同上下边界，视觉上像没有放齐。
修订应给每张图固定物理尺寸的正方形小轴，统一基线和边框，按实际像素检查正方形。
不要只把aspect='auto'改成'equal'就结束：整张流程图的坐标布局可能因此被整体压缩。

未发现两个技术图生成器使用旋转/倾斜变换。真实图片中的物体本来就可能倾斜，不能任意旋转
“扶正”；当前证据支持拉伸问题，不支持把所有看着歪的物体归因于旋转bug。
