# 开题备选 B｜异构联邦学习中普通图像损坏的协作失效

状态：待审阅的实验设计。数据、独立入口及 Kaggle Notebook 尚未生成。本文可直接上传至 ChatGPT 网页端。早先的《开题选题讨论》用于发散选题，这份材料用于审查一个具体实验能否支撑开题。

## 1. 大论文想回答什么

暂定题目为《图像损坏下模型异构联邦学习的协作失效与鲁棒性研究》。我希望这个方案能独立于 CLE 小论文成立。两者都研究模型异构联邦学习与图像输入质量，但本方案只处理普通图像损坏，不设类别与损坏的定向绑定，也不依赖 DSA、PEW 或 BER。

核心问题是：**在目标客户端自己的数据、模型和本地训练完全相同，且全系统坏图总量不变时，仅重新分配其他客户端的坏图，是否能让完整 RAHFL 的协作收益从正变负？** 这里的“负”指目标客户端参加联邦训练之后，在同一损坏评估集上的准确率低于它自己独立训练。

- **第一项研究工作**是发现、量化并归因。先验证固定损坏预算下的分配效应，再检查效应是否跨种子、分配位置和模型配对复现，最后区分长期训练效应和单次协作更新效应。
- **第二项研究工作**是机制驱动的鲁棒协作。只有发现可复现的负迁移、能定位到可干预环节，且训练阶段有可用信号时，才提出独立方法。主要目标是在相同信息和训练预算下减轻负迁移，并在匹配的普通损坏协议上和完整 RAHFL 正面对比。方法形式尚未确定。
- **大论文结构**可安排为绪论、相关工作与设定、协作失效诊断、方法与验证、总结。12 月 10 日开题，题目锁定前应先有受控预检结果。是否纳入已有 CLE 工作以及学院的成果要求另与导师确认。CLE 扩展方案 A 继续作为备选。

## 2. 论文原设定和我们要加的对照

RAHFL 原文使用四个客户端架构 ResNet10、ResNet12、ShuffleNet、MobileNetV2，私有任务是 CIFAR-10 图像分类，公共蒸馏图像来自 CIFAR-100。原文设定每客户端 10,000 张私有图、5,000 张公共图、40 个预训练 epoch、40 轮协作、batch size 256，并报告不同损坏率及干净/损坏测试表现。AugHFL 和 RAHFL 已经研究了损坏客户端的协作问题。SIGMOD 2026 的近邻工作也考察了受损客户端比例和损坏类型的异质性。当前待审查的差异是**固定系统损坏总量、目标客户端保持不变、以保留同样鲁棒本地目标的 Local 为对照，估计目标客户端的协作收益是否翻负**。这是待核验的研究问题，尚未宣称首创。

原文见 [RAHFL §III–IV](https://arxiv.org/html/2503.09206v1)、[AugHFL](https://openaccess.thecvf.com/content/ICCV2023/html/Fang_Robust_Heterogeneous_Federated_Learning_under_Data_Corruption_ICCV_2023_paper.html) 和 [SIGMOD 2026 §5.3](https://fardatalab.org/sigmod26-fl.pdf#page=14)。

### 首轮数据规格，待确认后冻结

| 数据角色 | 拟用样本与规则 |
| --- | --- |
| 私有训练 | 从 CIFAR-10 的原始训练划分选出 8,000 张，四客户端互斥，每客户端 2,000 张，每类 200 张。架构顺序沿用原文，预指定客户端 0（ResNet10）为主观察对象。 |
| 公共蒸馏 | 固定 1,000 张 CIFAR-100 训练图像及其顺序，蒸馏只读取图像。两条 HFL 臂读取同一批次。 |
| 路由验证 | 从 CIFAR-10 原始训练划分另取 1,000 张分层图像作为所有客户端共用的有标签路由验证集，三臂数据固定。建议首轮固定干净图像；它只提供排名，不回传梯度。 |
| 预检评价 | 从 CIFAR-10 原始训练划分再留出 1,000 张分层源图，与训练和路由验证互斥。每张源图保留干净视图，并生成高斯噪声、散焦模糊两种固定严重度 3 的视图。预检结果只支持开题决策。 |
| 正式确认 | CIFAR-10 原始 test split 保留给后续确认性评价。规则、主指标和模型选择冻结后再开启，标签不参与训练、路由、调参或早停。 |

每客户端和每个类别内按配额选择受损图像，保持任务标签不变。两种损坏各占坏图数的一半，严重度都固定为 3。均匀分配的四客户端坏图数为 `1000/1000/1000/1000`，集中分配为 `1000/1000/400/1600`，两种设置都恰好 4,000 张坏图，高斯噪声和散焦模糊各 2,000 张。客户端 0、1 的训练源图 ID、标签、损坏选择、参数和生成后像素在两种设置中逐项相同。客户端 2、3 的源图划分不变，仅按预先生成的配额清单增减损坏；两设置共有的受损样本保持其损坏参数不变。生成器输出源图、类别、角色、客户端、损坏类型、严重度和生成种子的清单及哈希。

这是**以原论文为参照的受控扩展**。等样本量、互斥分区、固定损坏类型、缩短训练和路由/评价隔离都是主动设计。结论先限定在该协议和测试损坏上。

## 3. 三臂怎么配对

| 实验臂 | 训练输入 | 协作 | 用途 |
| --- | --- | --- | --- |
| `local` | 只训练客户端 0，使用上面固定的训练数据 | 关闭公共前向、蒸馏和通信更新，保留同样的本地 AugMix/JSD/DCL | 客户端 0 的独立训练基准 |
| `hfl_uniform` | 四个客户端，坏图均匀 | 完整本地目标和 RAHFL 按准确率排序的选择性蒸馏 | 估计均匀分配下的协作收益 |
| `hfl_concentrated` | 四个客户端，坏图集中 | 与 `hfl_uniform` 同一算法、验证集和公共数据 | 估计只改其他客户端损坏分配后的协作收益 |

三臂复用客户端 0 的同一份预训练权重并对齐初始优化器状态、私有采样、增强种子、每轮本地 batch 数和更新次数。两个联邦臂还对齐公共输入、路由更新频率和协作预算。客户端 2、3 的预训练分别使用自己所在设置的私有数据，从相同随机初始化开始，避免用一个数据设置训练出的权重替代另一个设置的起点。首轮建议 `train_seed=0`，预训练 5 个 epoch、协作阶段 8 轮、每轮一个本地 epoch、私有 batch size 64、公共 batch size 128。以上是暂定的 Kaggle 预检预算，先 smoke 和计时，必要时在看任何准确率前调小并统一冻结。结果按预先固定的终止轮读取。

## 4. 什么算失效

对同一预检评价集，将两种损坏上的准确率等权平均，记三臂客户端 0 的结果为 $A_L,A_U,A_C$。

- $G_U=A_U-A_L$ 是均匀分布下的协作收益，$G_C=A_C-A_L$ 是集中分布下的协作收益。
- $\Delta=G_C-G_U=A_C-A_U$ 衡量改变其他客户端损坏分配后，目标客户端的协作收益变了多少。
- **核心信号**是 $G_U>0$ 且 $G_C<0$。首轮建议用 $G_U\ge +1.0$ 个百分点且 $G_C\le -1.0$ 个百分点作为值得投入复验的实用阈值，运行前锁定。这是项目决策阈值，统计证据另算。
- 若 $G_C<G_U$ 但 $G_C>0$，结论是“收益削弱”。若 $G_U<0$ 且 $G_C<0$，结论是“两种设置都出现负迁移”。若结果靠近零、优化未稳定或配对检查失败，首轮判为不确定。单次结果不能给全局结论。

同时记录干净准确率、每种损坏的准确率、其他客户端结果、每轮路由分数和教师边。主要图画目标客户端三臂损坏准确率和两条协作收益。两种损坏视图来自同一源图，置信区间按源图配对重采样，不能用来代替训练种子复验。

若达到预检门槛，先保持训练种子固定、交换客户端 2 和 3 的高低损坏位置，再保持分配固定、换训练种子复验。这两种变化分别检验位置依赖和训练随机性。现象稳定后，从同一个 checkpoint 分叉，对照执行与跳过同一轮协作更新，并保持后续本地更新一致。四个客户端的训练网络相互作用，三臂可识别这次损坏重分配的系统效应，不能凭教师边日志单独断言是哪位教师造成了损失。若只在低预算早期出现掉点，应检查更长、已匹配的训练阶段后是否还存在。

## 5. 实现边界与 Kaggle 验收

- 仓库已有 `RAHFL-master` 作者代码快照，关键入口是 `HHF/RAHFL.py`、`Network/pretrain.py` 和 `Dataset/init_dataset.py`。本地快照的默认数据入口读取一个全局 `corrupt_rate` 对应的数组，主循环的 `test_dl` 既参与蒸馏对象排序，也用于最终评价，设备列表还写死了四个索引。首轮需要给外层数据入口接入客户端级清单、单独路由验证集、独立评价集和单 GPU 配置。
- **建议保留作者快照，另建独立实验入口。** 可以从该快照做薄适配，保留训练损失、蒸馏规则和训练顺序。另一条工程途径是复用仓库已有的 `run_experiment.py` 和 `rahfl_asymhfl.py`，先核对本地目标、教师选择条件、训练顺序、优化器、BN 行为和批次预算。实现报告必须写清采用哪条路径和已知差别，不能把改过数据角色的预检称为原论文复现。
- 需实现四项交付。数据生成及输入合同，三臂配置及独立入口，自动核验及分析，以及 Kaggle 私有 Notebook 的可复制单元和启动卡。训练前核对目标客户端张量与标签哈希、训练/路由/预检/正式测试无交叉、坏图总数与构成、公共批次和训练预算。Smoke 中还需核对本地批次轨迹及 `local` 无公共前向或更新。
- 顺序为本地小样本 smoke，Kaggle 单张可用 GPU 计时，冻结预算后运行完整短预检。每臂结束保存权重、配置、日志、预测、路由记录和输入哈希；如估计会话会超时，分臂保存并在已保存 Notebook 版本的 Output 中确认产物。完整续训另验证模型和优化器等状态。计时和 smoke 不作科学结果。启动卡在实现及验证后填实际源码版本、输入包哈希、命令、输出文件名和已建的接收目录。
